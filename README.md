# 智药有方 · 安心药伴

将“智药有方”的药品识别、结构化药品说明与联合用药知识，融合到“安心药伴”的适老化、本地用药档案、提醒和家属协同架构中。

> 本项目是老人安全用药与家庭协同的 AI Web 应用，不诊断疾病、不推荐新处方、不替代医生或药师。药品和本草资料均明确标记为待专业复核。

## 核心能力

### 老人安全用药

- 今日用药、按时提醒、稍后提醒、漏服分支；
- 服用药物的计划时间和实际记录时间；
- 大字/特大字、高对比度、语音识别和朗读；
- 服务端账号与家庭关联，支持手机、平板和电脑跨设备登录；
- 本地持久化与家庭连接码跨设备摘要；
- 老人主动报告不舒服、SOS 和家属通知；
- 数据授权、导出、删除和审计。

### 识药与问药

- 药品包装拍照、相机实时取景、相册兜底；
- 问药首页采用单一大画布，包含居中提问、问药/识药切换、推荐问题和一体化输入栏；
- 本地中文 OCR 自动填充药名、成分、剂量、次数和时间；
- AI 视觉候选识别与本地 OCR 并行，照片保留在对话中，可继续追问“这个药”；
- 自动检查重复成分、身体情况和当前联合用药风险；
- 具体药名、剂型、规格和问题分别回答，不复用同一条通用文案；
- 可接 OpenAI 兼容视觉模型进行药品或药材图片候选识别；
- 无视觉模型 Key 时仍保留本地 OCR、药品搜索与手动录入。

### 药品百科

- 149 种结构化药品条目；
- 通用名、商品名、成分、剂型和规格检索；
- 参考用法、每日上限、服用时机、饮食注意；
- 常见不良反应、特殊人群提醒和就医信号；
- 28 条确定性相互作用与重复用药规则；
- 20 类通用用药安全主题，覆盖漏服、重复服药、饮酒、剂型破坏、储存、抗生素、降糖药、抗凝药、保健品和中药；
- 109 个可重复安全评估场景与模型对照实验；
- 多药对账：一次加入处方药、OTC、中药材和保健品，生成完整清单；
- 自动检查相同成分、同类药重复、已知相互作用和错峰服用要求；
- 同服药物选择、风险分级和打印摘要能力的数据基础。

### 中草药识别与本草资料

- 14 种常见中药材条目；
- 名称、别名、性味、归经、传统功用和辨识要点；
- 老人、抗凝药、慢病用药等安全提醒；
- 拍照候选识别接口与药材名称搜索；
- 不提供自行配伍、剂量或“替代处方药”建议。

## 页面结构

老人端保留四个一级入口：

- **问药识药**：AI 问药、拍照识药、药品百科、识中药材；
- **今日**：下一次服药、提醒、服药记录；
- **用药**：当前用药、手动录入、提醒开关；
- **我的**：大字、朗读、通知、家属授权和数据。

家属端保留：

- 家人概览；
- 风险提醒；
- 用药摘要；
- 授权范围。

## 快速运行

在 macOS 上可双击 `一键启动智药有方-安心药伴.command`；Windows 可双击同名 `.cmd` 文件。

```bash
npm install
cp .env.example .env
npm run dev
```

打开：

- Web：`http://localhost:5174`
- API：`http://localhost:8788`

生产预览：

```bash
npm run build

```

访问 `http://127.0.0.1:8788`。

## 可选 AI 配置

```dotenv
PORT=8788
APP_ORIGIN=http://localhost:8788
AI_BASE_URL=https://api.openai.com/v1
AI_API_KEY=your-key
AI_MODEL=your-text-model
AI_VISION_MODEL=your-vision-model
AI_ASR_MODEL=
QWEN_ASR_MODEL=
QWEN_TTS_MODEL=
QWEN_CUSTOM_TTS_MODEL=
DASHSCOPE_TTS_BASE_URL=
VAPID_CONTACT=mailto:your-email@example.com
```

用途：

- `AI_MODEL`：低风险普通问药的表达润色；
- `AI_VISION_MODEL`：药品与中药材图片候选识别。
- `AI_ASR_MODEL` / `QWEN_ASR_MODEL`：语音转写模型。
- `QWEN_TTS_MODEL` / `QWEN_CUSTOM_TTS_MODEL`：固定音色和专属音色合成模型。
- `DASHSCOPE_TTS_BASE_URL`：兼容服务使用非默认语音接口地址时填写。
- `VAPID_CONTACT`：Web Push 服务联系人，正式部署时填写有效邮箱。

配置可用 Key 后，普通问答、风险解释和多轮对话由智能模型负责组织表达；本地规则负责先确定风险等级、资料不足和用药停止线，模型不得覆盖这些结论。密钥文件 `.env` 已被 Git 忽略。

也兼容参考项目的 `DASHSCOPE_API_KEY`、`QWEN_TEXT_MODEL`、`QWEN_VISION_MODEL` 变量；如使用百炼专属业务空间，请同时配置对应的完整 `AI_BASE_URL`。

高风险药物问题始终由本地确定性规则控制，模型不能绕过停药、调剂量和补服限制。

## 数据与安全

- 账号、密码摘要、会话和家庭关联保存在服务端，密码使用 scrypt 加盐摘要；
- 浏览器使用 IndexedDB 缓存当前设备的工作区，断网时仍可读取已缓存内容；
- 刷新、关闭和重启后可恢复；
- 家庭摘要不包含完整对话和原始药品图片；
- 药品和本草图片默认只在当前请求中使用；
- 价格无法从可靠实时来源获取时明确显示“暂无可靠价格”，不猜价；
- 全部药品和本草资料仍标记为 `pending_review`；
- 本草资料整理自公开资料，需要专业审核后才能用于真实医疗场景；
- 正式部署应启用 HTTPS、数据库加密、访问审计和备份。

## Agent 与 MCP

问药 Agent 使用可解释工具注册表执行药品检索、相互作用核查、个人档案读取和服药日程查询。服务端同时提供受账号会话保护的 MCP JSON-RPC 工具接口，详见 [`docs/MCP接口.md`](docs/MCP接口.md)。

当前演示主链路由前端确定性规划器选择只读工具，大模型负责在安全证据范围内组织回答。服务端保留了函数调用接口，但为避免增加首屏等待，默认问答链路不额外请求模型自主选择工具。MCP 工具调用和本地 Agent 阶段事件均已实现。

## 安全边界

- 不诊断疾病；
- 不开具或修改处方；
- 不提供自行停换药和调整剂量；
- 高危药物漏服时不生成具体补服方案；
- 不把相似图片/相似药名直接认定为同一药物；
- 不把中药称为没有副作用的天然药；
- 不提供实时最低价、平台排行或医保报销结论；
- 出现胸痛、呼吸困难、意识异常、严重过敏或明显出血时立即使用 SOS/120。

## 技术架构

```text
React + TypeScript + Vite
        │ REST / SSE
        ▼
Node.js HTTP 服务
  ├─ 账号、会话与家庭关联
  ├─ 确定性用药安全规则
  ├─ 多模态模型接口
  ├─ MCP 只读工具
  └─ JSON 运行数据与 Web Push
        │
        ▼
浏览器 IndexedDB 本地缓存
```

前端采用 React Router 做页面路由和懒加载，Zustand 管理运行状态，IndexedDB 保存本地工作区。后端使用 Node.js 原生 HTTP 服务，当前以 JSON 文件持久化，通过 SSE 将老人端更新实时推送到另一台设备或家属端。
