# 安心药伴 5–8 分钟演示脚本

## 录制前准备

- 运行 `npm run build && npm start`。
- 使用 Chrome 或 Edge 打开 `http://localhost:8787`。
- 在“我的”点击“恢复演示数据”。
- 检查麦克风、扬声器和通知权限。
- 准备一台第二设备或第二个浏览器 Profile，用于展示家庭连接码同步。
- 全片明确说明：内置医药规则是比赛演示素材，尚未完成临床审核。

## 0:00–0:40 项目介绍

画面：老人端首页。

讲解：

> 很多老人不是不会用手机，而是一次要记太多药、看不清说明书，也分不清药物重叠和漏服风险。安心药伴不是诊断工具，而是一个适老化的安全用药入口：语音和拍照降低操作门槛，AI Agent 负责交叉核对，高风险时主动停下来。

## 0:40–1:40 适老化首页

操作：

1. 展示首页唯一的下一步用药卡。
2. 指出“已经吃啦”“等会儿提醒”“没有服用”。
3. 点击“预览全屏提醒”，展示大字、语音和震动。

讲解：

> 首页不堆功能，只回答现在要做什么。核心操作不超过两步。没有确认也不会被直接算成漏服。

## 1:40–3:30 拍照加药与高危限制

操作：

1. 返回首页，点击“拍药盒”。
2. 点击“使用演示药盒”。
3. 等待本地中文 OCR。
4. 展示原图、字段置信度和人工修改。
5. 点击“我已核对，开始安全核查”。
6. 展示“高危 · 先问医生”和依据。
7. 指出按钮只有“只保存到待核对清单”。

讲解：

> 识别不是自动入档。低置信字段必须确认，因为医疗场景里“看起来差不多”可能是另一种药。这次识别到华法林，与当前清单中的阿司匹林形成需要医生核对的高危组合。Agent 停止生成停药、调剂量或补服建议，只保存为待核对记录。

## 3:30–4:50 语音问药、RAG 与 Agent

操作：

1. 打开“问药”。
2. 点击“华法林和阿司匹林能一起吃吗？”或使用语音输入。
3. 展示处理阶段。
4. 展示结论、下一步、高风险标记。
5. 展开“查看依据与核查范围”。

讲解：

> 回答不是先长篇解释，而是先给结论。第二层才展示当前用药、触发原因和来源。高风险问题由本地策略控制，大模型不能绕过。没有资料时，系统会明确说资料不足。

## 4:50–6:10 家属跨设备协同

操作：

1. 老人端打开“我的”，复制家庭连接码。
2. 在另一设备切换到家属端并输入连接码。
3. 展示家属概览和风险摘要。
4. 打开“授权”，展示老人可关闭用药摘要、漏服和 SOS 联系权限，高危提醒不可静默关闭。

讲解：

> 家属只看到授权摘要，而不是完整对话和逐条隐私日志。家属不能被设计成远程监控者，也不能代替老人点击已服药。老人有知情权和叫停权。

## 6:10–7:10 提醒、漏服与 SOS

操作：

1. 老人端打开一条待确认药物，点击“没有服用”。
2. 记录状态并展示漏服处理。
3. 打开 SOS。
4. 展示 120/110 一键拨号和授权家属通知。

讲解：

> 普通 Web 页面不能静默拨打急救电话，所以产品不夸大成自动救援。页面提供独立于模型的拨号入口，并通过后端推送把必要摘要发给授权家属。

## 7:10–8:00 技术亮点与总结

操作：

1. 返回问药页。
2. 展示本地持久化、同步状态和来源。
3. 可打开“我的”展示审计、导出与删除。

讲解：

> 技术上使用 React、TypeScript 和 Vite，本地 OCR 离线运行，IndexedDB 保证刷新重启不丢数据，Node 服务负责家庭摘要与推送，可选大模型只在低风险路径负责表达润色。我们的核心创新不是让 AI 更大胆，而是让 AI 在老人用药场景里知道什么时候必须停下来。

## 结束语

> 安心药伴希望让老人少学一步、少漏一次、少一次危险叠加，也让家属只在真正需要时介入。
