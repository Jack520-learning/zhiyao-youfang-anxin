# 安心药伴技术方案

> 版本：V1.0  
> 日期：2026-11-14  
> 对应实现：AI Web 应用原型

---

## 1. 技术目标

本方案解决四个工程问题：

1. 老人端在没有键盘、看大字、语音表达不标准的情况下仍能完成任务；
2. AI 回答前必须读取当前完整用药档案，并在高风险时切换受限模板；
3. 本地数据必须跨刷新和重启保留，同时支持家属跨设备摘要；
4. 无外网模型或通知权限时，核心安全路径仍能演示。

## 2. 总体架构

```text
React / TypeScript / Vite
├─ 适老化页面与设计系统
├─ Web Speech：语音识别与朗读
├─ Tesseract.js：离线中文 OCR
├─ PWA / Service Worker
├─ Zustand
└─ IndexedDB
        │
        ├─ 本地规则引擎
        ├─ 本地 RAG 演示知识库
        └─ 本地优先同步
                │
Node HTTP API
├─ 家庭摘要同步
├─ 共享连接码
├─ 定时提醒扫描
├─ Web Push / VAPID
├─ SOS 摘要通知
└─ 可选 OpenAI 兼容模型代理
```

说明：

- V1 使用 Node 内置 `http`，减少原型后端依赖。
- 家庭状态保存在本地 JSON 数据仓，正式环境应替换为经过认证的数据库。
- OCR Worker、WASM 和中文语言包复制到 `public/ocr`，不依赖 CDN。

## 3. 前端设计

### 3.1 技术栈

- React 19
- TypeScript
- Vite
- React Router
- Zustand
- idb-keyval
- Lucide React
- Tesseract.js

### 3.2 路由

| 路由 | 页面 |
|---|---|
| `/` | 按角色进入老人首页或家属概览 |
| `/chat` | 语音/文字问药 |
| `/medications` | 用药清单 |
| `/medications/:id` | 药物详情和核查 |
| `/add-medication` | 拍照、识别、确认和风险结果 |
| `/reminder/:id` | 明确未服后的漏服处理 |
| `/family` | 家属概览 |
| `/safety` | 风险提醒 |
| `/profile` | 授权、通知、数据权利和演示设置 |

### 3.3 适老化

- Design Token 统一字号、颜色、间距、圆角和触控尺寸。
- 主要按钮最小 60px 高，导航触控区域不小于要求。
- 正文在移动端使用 18px 以上字号，强调信息进一步放大。
- 风险同时使用文字、图标和背景，不只使用颜色。
- 语音失败时保留完整点击和文字输入通道。
- 页面切换自动回到顶部，避免保留上一页滚动位置。
- 尊重 `prefers-reduced-motion`。

## 4. 状态与数据持久化

### 4.1 Zustand

全局状态包含：

- 老人档案、疾病和过敏史；
- 紧急联系人和共享授权；
- 处方药、OTC、保健品与停用药物；
- 服药计划与执行记录；
- OCR 草稿；
- 风险核查记录；
- 对话和来源；
- 审计日志；
- 同步与本地保存时间。

### 4.2 IndexedDB

使用 `idb-keyval` 实现 Zustand 的持久化存储：

1. 首次打开写入演示档案；
2. 更新药物、草稿、服药状态或授权后自动持久化；
3. 刷新、关闭和重启后通过 Zustand hydration 恢复；
4. IndexedDB 读取异常时设置超时兜底，避免页面永久停留在加载状态。

### 4.3 跨设备同步

老人端只同步 `CloudSnapshot`：

- 老人称呼、年龄、疾病和过敏史；
- 授权状态；
- 当前/待核对药物；
- 服药事件；
- 最近风险核查；
- 紧急联系人。

不向家庭摘要同步：

- 完整对话；
- 原始药盒图片；
- 本地审计详情；
- 已停用且无风险关联的历史药物列表。

家属端每 5 秒读取一次摘要。老人端状态变化后延迟 1 秒同步，减少频繁写入。

## 5. 多模态录入

### 5.1 图片

1. 浏览器读取相机或相册文件；
2. Canvas 将图片压缩到最大 1800px；
3. 原图以 JPEG Data URL 保存到本地草稿；
4. Tesseract Worker 从 `public/ocr/lang` 加载 `chi_sim`；
5. OCR 返回全文和整页置信度；
6. 规则提取药名、剂量、频次、饭前饭后和时间；
7. 关键字段缺失或整页置信度低于 72% 时要求人工确认；
8. 用户确认后才进入风险核查。

### 5.2 语音

- Web Speech Recognition 用于中文语音转写；
- Speech Synthesis 用于回答、提醒和操作反馈；
- 不支持语音时展示文字输入和点击路径；
- 麦克风或语音服务失败时不阻塞其他操作。

## 6. 安全 Agent 工作流

标准链路：

```text
用户问题
  → 意图识别
  → 读取当前全部药物
  → 检查药物成分、疾病与过敏史
  → 检索演示知识库
  → 风险分级
  → 安全模板 / 可选大模型润色
  → 来源与审计
```

### 6.1 风险等级

| 等级 | 系统能力 |
|---|---|
| low | 解释、来源和一般下一步 |
| medium | 要求补问、纠错或联系专业人员 |
| high | 禁止具体停药、调剂量、补服方案 |
| unknown | 明确资料不足，停止推断 |
| emergency | 切换 SOS，不等待模型分析 |

### 6.2 大模型边界

- 本地规则先做风险判断。
- 仅低风险结果允许调用模型润色。
- 高危、中危、资料不足和紧急情况直接使用本地安全模板。
- 模型 API 密钥只保存在服务端环境变量。
- 传给模型的上下文是最小化药物、疾病和过敏字段。

模型无配置时，系统仍可完整演示 Agent 阶段、风险分级、来源和受限回答。

## 7. RAG 演示知识库

`shared/knowledge.json` 包含：

- 来源条目；
- 老人可理解的回答条目；
- 相互作用规则；
- 高危药物清单；
- 紧急身体状态关键词。

当前知识库标记为 `unreviewed-demo`。正式上线前必须：

1. 替换为经授权的说明书和临床资料；
2. 由医药专业人员审核规则；
3. 为知识条目增加版本和生效时间；
4. 处理不同说明书版本之间的冲突；
5. 对高危规则进行专项测试。

## 8. 提醒与通知

### 8.1 页面内提醒

- 到达用药窗口时出现高对比全屏卡片；
- 支持大字、语音和震动；
- 主操作只有“已经吃啦”和“等会儿提醒”；
- 关闭当前提醒不等于漏服。

### 8.2 后端提醒

Node 服务每 30 秒扫描一次家庭摘要：

- 用药计划到达当前时间时发送第一条推送；
- 5 分钟后仍未确认时发送第二条；
- 每 24 小时、每种药、每个时间窗口都有去重键；
- 家属只在超过 90 分钟仍未确认时收到异常提示；
- 订阅失效时自动清理 Web Push endpoint。

### 8.3 设备降级

| 能力 | 不可用时的替代 |
|---|---|
| 系统推送 | 页面内全屏提醒 |
| 语音 | 大字和点击 |
| 震动 | 屏幕高对比与动效 |
| 自动播报 | 可点击朗读按钮 |
| 静默紧急外呼 | 120/110 一键拨号 |

## 9. API

| 方法 | 路径 | 用途 |
|---|---|---|
| GET | `/api/health` | 服务与 AI 配置状态 |
| PUT | `/api/sync` | 更新家庭安全摘要 |

## 10. 隐私与安全控制

- 医疗敏感信息不写入前端日志。
- 大模型密钥不进入客户端包和 Git。
- 家属只接收摘要，不接收完整对话。
- 当前用药、未确认和紧急信息分别受授权开关控制。
- 高危共享不可在界面静默关闭。
- 用户可导出和删除本地数据，并尝试同步删除云端摘要。
- 外部说明书、图片和网页文字被视为资料，不作为可执行指令。

正式上线前仍需要：

- 账号认证、多因素认证和权限审计；
- HTTPS、数据库加密和密钥托管服务；
- 数据保留与删除合规；
- CSRF、速率限制、上传扫描和越权测试；
- 医药内容审核流程。

## 11. 测试策略

当前自动化测试覆盖：

- 华法林与阿司匹林高危识别；
- 高危漏服不生成补服剂量；
- 紧急症状优先进入求助模式；
- 资料不足时停止回答；
- 重复有效成分识别；
- 假设同服不错误声称已在当前清单。

浏览器验收覆盖：

- 桌面和 390px 手机布局；
- 本地中文 OCR；
- 字段人工确认；
- 高危结果与待核对状态；
- 页面刷新后的 IndexedDB 恢复；
- 家庭摘要 API；
- 浏览器控制台错误检查。

## 12. 已知限制

- 家庭连接码不是生产级身份认证；
- JSON 文件数据仓只适合演示和小规模试用；
- 演示知识库未完成医药专业审核；
- 关闭页面推送需要 HTTPS、通知授权和支持 Web Push 的环境；
- 120/110 不能由普通网页静默自动拨打；
- 物理 SOS 按钮和灯光尚未接入专用硬件；
- 可选大模型接口当前返回结构化 JSON，而不是逐 token 流式协议。
